# content-fetch-gateway-java

面向多来源的内容获取网关：从多个内容提供方拉取**内容寻址**（content-addressed）的数据，
对上层提供稳定且一致的读取。所有来源与异常场景均可在本地用测试替身
（`FakeContentSource`）模拟，不依赖外部服务或真实凭据。

## 读取入口

```
GET /gateway/content/{cid}
```

`cid` 形如 `sha256:<hex>`，即完整内容的 SHA-256。响应头：

- `X-Content-Source`：实际提供内容的来源 id，缓存命中时为 `cache`
- `X-Content-From-Cache`：是否来自缓存

所有来源不可用、校验不通过、超时或被取消时返回 `502`。

## 一致性语义

1. **完整性校验**：内容按分块拉取，每个分块先对照来源清单（manifest）中的分块哈希校验，
   全部拉取完成后再对照 `cid` 做整体哈希校验。两级校验全部通过的内容才会对读取方可见。
2. **单一来源副本**：返回的内容一定是来自**同一个来源**的完整副本。
   暂存按 `(cid, sourceId)` 隔离，切换来源时从头拉取，不同来源的片段绝不拼接。
3. **分块续传**：已校验通过的分块即时落盘到暂存区。获取中断（抖动、取消、超时）后，
   再次获取同一内容时从已校验位置继续，已校验分块不重复下载、不重复落盘
   （完成后暂存文件**原子移动**进缓存，而非重写）。若来源清单发生变化，
   旧暂存会被丢弃并从头拉取。
4. **来源降级**：来源持续失败或返回损坏内容时触发熔断（损坏按两次失败计），
   OPEN 期间退出调度；冷却期满进入 HALF_OPEN 放行一个探测请求，
   探测成功即恢复调度，失败则重新熔断。
5. **请求合并**：同一 `cid` 的并发读取合并为一次实际回源；缓存命中直接返回，
   不进入回源流程，慢来源不会拖垮缓存已可用的读取。
6. **缓存一致性**：缓存条目带 TTL，过期不返回；读取时重新校验内容哈希，
   损坏条目自动清除（自愈）并按未命中回源。缓存条目写入后不可变，
   淘汰不影响已经拿到字节副本的读取方。
7. **取消与超时**：取消或超时的获取只会在暂存区留下已校验分块（供续传），
   未完成的内容永远不会被后续读取当成可用结果。

## 配置项（`gateway.*`）

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `gateway.cache-dir` | `./data/cache` | 已校验内容的缓存目录 |
| `gateway.staging-dir` | `./data/staging` | 下载中内容的暂存目录 |
| `gateway.cache-ttl` | `10m` | 缓存有效期，过期后访问回源 |
| `gateway.fetch-timeout` | `30s` | 单次获取的整体超时 |
| `gateway.failure-threshold` | `3` | 来源连续失败达到该次数后熔断 |
| `gateway.open-cooldown` | `30s` | 熔断持续时间，到期后进入探测 |

## 接入新来源

实现 `ContentSource` 接口并注册为 Spring Bean 即可参与调度：

```java
public interface ContentSource {
    String id();                 // 来源唯一标识
    int priority();              // 优先级，数值越小越优先
    TrustLevel trustLevel();     // 可信度，同优先级时高可信先调度
    ContentManifest manifest(String cid);       // 分块清单
    byte[] fetchChunk(String cid, int index);   // 拉取分块
}
```
